# 05 — Решения и открытые вопросы

## Принятые решения

### D-001 · Скоуп v1 — полный аналог бота
**Решение:** webapp повторяет всю функциональность бота, кроме голосового/AI-ввода и PDF-импорта.

**Почему:** бот остаётся каналом быстрого ввода, webapp — каналом просмотра и управления.
Половинчатый вариант («только просмотр») заставил бы юзера прыгать между ботом и webapp
для рутинных правок.

**Цена:** большой объём работ, поэтому разбит на 6 фаз с рабочим результатом после фазы 3.

---

### D-002 · Стек фронтенда — React + Vite + TypeScript
**Решение:** отдельная папка `webapp/`, сборка в статику.

**Почему:** стандарт для Telegram Mini Apps, есть официальный `@telegram-apps/sdk-react`.
Графики и формы на голом JS быстро упрутся в потолок сопровождаемости.

**Альтернатива, которую отклонили:** голый HTML+JS в `resources/static` — проще стартовать,
но отчёты с интерактивными графиками писать тяжело.

---

### D-003 · Хостинг — та же VM, один домен
**Решение:** nginx на `93.170.72.82`: `/` — статика, `/api` — Spring Boot. Let's Encrypt.

**Почему:** фронт и API на одном origin, поэтому CORS не нужен и initData не уходит
на сторонний домен. Всё в одном месте — проще деплой и отладка.

**Альтернатива, которую отклонили:** фронт на Vercel/Netlify — бесплатный HTTPS,
но нужен CORS и разъезжаются окружения.

---

### D-004 · Аутентификация — initData на каждом запросе, без сессий
**Решение:** заголовок `Authorization: tma <initData>`, валидация подписи при каждом обращении.

**Почему:** initData самодостаточна и подписана ботом. Сессии/JWT добавили бы состояние
и второй источник правды об истечении срока. TTL 24 ч уже зашит в валидатор.

**Риск:** валидация HMAC на каждом запросе. Стоимость операции ничтожна на текущих объёмах.

---

### D-005 · Общий сервисный слой, без дублирования логики
**Решение:** контроллеры вызывают те же сервисы, что и бот. Лимиты тарифа, проверки владельца,
валидация — в сервисах.

**Почему:** любое расхождение правил между ботом и webapp — это баг, который трудно заметить.
Уже существующие sealed-результаты (`CategoryCreationResult`, `GroupCreationResult`,
`NotificationCreationResult`) отлично ложатся на HTTP-коды.

---

### D-006 · Отчёты отдают данные, а не размеченный текст
**Решение:** опубликовать `build*`-методы `FinanceReportService`, отдавать `ReportData`-модели.
Telegram-HTML-форматирование остаётся только для бота.

**Почему:** `generate*Report()` возвращают строку с `<b>`, `<pre>` и ASCII-барами — для webapp
непригодно. При этом расчёт уже отделён внутри класса, публиковать почти нечего.

---

### D-007 · Онбординг остаётся в боте
**Решение:** Mini App не проводит онбординг. Пользователь без групп получает `activeGroupId: null`,
фронтенд предлагает сначала запустить бота. Смена языка в webapp идёт через тот же
`OnboardingService.selectLanguage`, что и в боте.

**Почему:** Mini App открывается из бота, до него почти всегда доходят уже прошедшие онбординг.
Дублировать выбор языка и валюты ради редкого входа по прямой ссылке не стоит.
Общий `selectLanguage` нужен, чтобы смена языка из webapp не сломала онбординг бота:
бот решает, показывать ли выбор языка, по `language == null`, а личную группу создаёт именно этот шаг.

### D-008 · JSON web-слоя — Jackson 3
**Решение:** web использует `JsonMapper` (Jackson 3), который собирает Spring Boot 4.
Конвенции API (`BigDecimal` и `ObjectId` строками) — бин `JacksonModule`.

**Почему:** в Spring Boot 4 MVC по умолчанию работает на Jackson 3, Jackson 2 API помечен deprecated.
Бин `ObjectMapper` (Jackson 2) объявлен `chat-machinist` для бота — web от него не зависит,
иначе web-слой не поднимается без фреймворка бота.

## Открытые вопросы

### Q-001 · Домен для Mini App
Нужно купить домен и направить на VM. Без него Telegram не примет Mini App — требуется HTTPS
с валидным сертификатом. Блокирует W-020.

**Нужно от владельца:** выбрать и купить домен.

---

### Q-002 · Библиотека графиков
Не выбрана. Критерии: небольшой вес, работа с тёмной темой Telegram, поддержка нужных типов
(столбцы, линии, доли). Решать при подходе к W-012.

---

### Q-003 · Судьба persistent-кнопок бота
После появления webapp часть нижних reply-кнопок (Отчёт, Записать доход/трату) дублирует
функциональность Mini App. Возможно, их стоит заменить одной кнопкой открытия webapp.

Решать после того, как webapp заработает — на живом опыте, а не заранее.

---

### Q-004 · Активация подписки остаётся ручной
Webapp не решает проблему автоматической активации Premium: ни Tribute, ни Kaspi без API
не уведомляют бэкенд об оплате. В webapp — только ссылка на оплату, активация по-прежнему
через админскую команду `/activate`.

Автоматизация возможна только через Telegram Stars либо официальный Kaspi Business API —
это отдельная задача вне скоупа webapp.
