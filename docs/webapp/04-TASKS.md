### W-003 · Фильтр аутентификации по initData · DONE
**Критерии приёмки**
- [x] Сервлет-фильтр читает `Authorization: tma <initData>`, валидирует через существующий `TelegramInitDataValidator`
- [x] Валидная initData → `TelegramPrincipal` доступен контроллерам
- [x] Невалидная/просроченная/отсутствующая → `401` в едином формате ошибки
- [x] Фильтр применяется только к `/api/**`
- [x] Тесты: валидная, просроченная, подделанная подпись, отсутствующий заголовок

**Зависимости:** W-001

**Результат:**
- `TelegramAuthFilter` (`OncePerRequestFilter`) читает заголовок, отрезает схему `tma `,
  отдаёт остаток валидатору. Успех — принципал в `TelegramPrincipal.REQUEST_ATTRIBUTE`,
  иначе `401` и цепочка обрывается.
- Причина отказа не раскрывается: просрочка, подделка и отсутствие заголовка дают один ответ —
  различать их значит подсказывать тому, кто подбирает формат.
- Тело `401` пишет сам фильтр: фильтры работают раньше диспетчера, `@ControllerAdvice` их не ловит.
  Формат общий — `ApiError` + `ApiErrorCode`, W-004 подключит к ним глобальный обработчик.
- Регистрация через `FilterRegistrationBean` с паттерном `/api/*`, а не `@Component`:
  бин-фильтр иначе вешается на все пути, включая вебхук бота.
- 7 тестов фильтра: валидная, просроченная, подделанная подпись, чужой токен бота,
  без заголовка, чужая схема, формат тела ошибки. Мутация (пропуск без принципала)
  роняет все 6 отказных — тесты проверяют поведение, а не факт вызова.
- Хелпер подписи initData вынесен из теста валидатора в общий `TestInitData`.
  Константы HMAC в тесте продублированы намеренно: тест считает подпись независимо
  от прода, иначе он перестанет ловить подмену алгоритма.

**Не покрыто тестом:** ~~привязка фильтра к `/api/*`~~ — закрыто в W-004 (`ApiWebLayerTest`).

### W-004 · Базовый слой web: ошибки, DTO-конвенции, резолвер пользователя · DONE
**Критерии приёмки**
- [x] Глобальный обработчик исключений отдаёт единый формат ошибки из `03-API.md`
- [x] Сообщения об ошибках локализованы по языку пользователя (переиспользован `LocalizationService`)
- [x] Суммы сериализуются строками, `ObjectId` — строками, даты — ISO
- [x] Общий хелпер: принципал → `UserInfo`, проверка членства в группе (`403` при отказе)
- [x] Тесты на проверку доступа к чужой группе

**Зависимости:** W-003

**Результат:**
- `ApiException` + `ApiErrorCode` (код знает свой HTTP-статус и ключ сообщения) + `ApiErrorFactory`.
  `ApiExceptionHandler` ограничен пакетом `ai.moneymanager.web`, вебхук `chat-machinist` не задевает.
  Непредвиденные ошибки → `500 INTERNAL_ERROR` без внутренних деталей, стектрейс только в лог.
- Язык ошибки: `UserInfo.language` → `language_code` из initData → `ru`. 401 из фильтра — на `ru`,
  пользователь на этом шаге ещё не опознан.
- JSON на Jackson 3 (Spring Boot 4): бин `JacksonModule` подключается в `JsonMapper` Boot.
  `BigDecimal` → строка через `toPlainString` (без `1E+3`), `ObjectId` ↔ hex-строка, даты ISO.
  Добавлен `tools.jackson.module:jackson-module-kotlin`. Web-слой не зависит от Jackson 2 бина `chat-machinist`.
- `CurrentUserArgumentResolver`: параметр `UserInfo` в методе контроллера → пользователь из принципала,
  создаётся при первом входе.
- `GroupAccessGuard.requireMember`: нет группы → `404`, не участник → `403`.
- `UserInfoService.getOrCreate(TelegramProfile)` заменил `getUserInfo(User)`: сервис больше не знает
  о Telegram-библиотеке, бот и web создают пользователя одним путём.
- **Исправлен баг в боте:** пользователь искался сначала по username. Смена ника создавала дубликат
  (терялись группы), а новый владелец освободившегося ника получал чужой аккаунт. Теперь поиск только по `telegramUserId`.
- Тесты: `ApiWebLayerTest` (`@WebMvcTest`, 9) — реальная обвязка Boot: фильтр, JSON, резолвер, 400/403/404/500,
  локализация; `GroupAccessGuardTest` (4); `UserInfoServiceTest` (4). Мутации — поиск по username,
  фильтр не на `/api/*`, без проверки членства, без JSON-модуля — ловятся.
- Закрыт хвост W-003: привязка фильтра к `/api/*` проверена через `@WebMvcTest`.

### W-005 · Эндпоинт `/me` · DONE
**Критерии приёмки**
- [x] `GET /api/v1/me` отдаёт профиль, активную группу, тариф и лимиты (формат — `03-API.md`)
- [x] Пользователь создаётся при первом входе, как в боте
- [x] `PATCH /api/v1/me` меняет язык
- [x] Лимиты берутся из `SubscriptionLimitsService`, не хардкодятся

**Зависимости:** W-004

**Результат:**
- `MeController` + `MeResponseFactory`. Тариф считается по сроку: истёкший `PAID` отдаётся как `FREE`.
  Безлимит — `null`. `expiresAt` — ISO-8601 UTC.
- Язык в ответе — эффективный: выбранный → `language_code` из Telegram → `ru`.
- Пользователь без групп получает `activeGroupId: null`; личную группу создаёт онбординг бота (решение D-007).
- AI-лимиты перенесены в `SubscriptionLimitsService` — теперь все лимиты тарифа в одном месте;
  `AiRateLimitService` и экран подписки в боте читают их оттуда.
- **Онбординг вынесен в `OnboardingService`.** В боте выбор языка создаёт личную группу, если групп нет,
  а бот показывает выбор языка по признаку `language == null`. Если бы `PATCH /me` только менял язык,
  бот пропустил бы этот шаг и пользователь остался бы без группы. Теперь бот и web вызывают один `selectLanguage`.
  Заодно убран дубль: личная группа создавалась в двух местах, ключ имени был объявлен дважды.
- `PATCH` проверяет язык: не `ru`/`en`/`kk` → `400` с `details.supported`; пустое тело → `400`.
- Тесты: `MeControllerTest` (7, `@WebMvcTest`), `OnboardingServiceTest` (3). Мутации — без проверки языка,
  тариф без учёта срока, безлимит не `null`, онбординг без группы — ловятся.
- Общая настройка web-тестов вынесена: `@ApiWebLayerSetup` и фикстуры в `WebTestFixtures.kt`.
